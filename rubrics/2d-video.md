# 工作监督 · 判据（2D 科普动画剧 / 视频剪辑）

> 用途：判断器每轮拿这份判据去核对 AI 的实际动作。
> **铁律（AGENTS.md）**：写成"标准"的，必须能指到《权威依据清单》的出处；指不到的只能标"项目经验（非权威）"。
> 出处简写：`总清单§X` = 《每期要求总清单》；`依据§X` = 《权威依据清单》；`铁律N` = AGENTS.md 视频铁律。

## 适用范围
只在本轮任务**确实涉及视频/动画/剪辑制作**时启用；其它任务别拿这套去冤枉。

---

## A 轴 · 合理规范（有没有按标准做）

- A1 **8 道关卡逐关过，任一关没过不许进下一关**：C0内容→K0美术→K1分镜→K2设定→K3构图→K4作画→K5合成→K6完片。〔总清单§六〕
- A2 **开工后标准不再改**：要改先记进《待升级清单》，一期结束统一评审。〔总清单§六〕
- A3 技术硬指标：**1080×1920 / 30fps 恒定 / h264 / 码率≥8Mbps 或 CRF≤17 / 响度 -14.5±0.5 LUFS / 真峰 ≤-1.0 dBTP / 时长 60–90s（硬上限100s）**。〔总清单§四；依据§四：EBU R128、抖音官方指南〕
- A4 内容打分 **≥85** 才能往下做。〔总清单§二〕
- A5 情绪牵引一票否决：开场3秒抓人 / 每5秒一个事件 / **不许连续8秒无事件** / 疑问≤15秒给答案 / 全片≥3次起伏。〔总清单§二〕
- A6 开头 0–15s：**第一帧就有大字+画面**；**不许空白淡入、不许报栏目名**；开头2秒不乱动；15秒内不堆动效。〔总清单§二、§三〕
- A7 **每期至少 3 个关键镜是真画出来的**，不是把一张图推来推去。〔总清单§三〕
- A8 场景 ≥4 个（各有剧情理由）；核心道具 ≥3 件、至少 1 个特写且被角色用起来；相邻两镜运镜不重复；≥2 次反应特写。〔总清单§三〕
- A9 字幕不挡脸、不出安全区、最多两行；口型跟台词，眨眼 2–5 秒一次。〔总清单§三〕
- A10 每个数字都要有**来源 + 验证方法**（事实核查表）；没来源的不许用。〔总清单§二；依据§五〕

## B 轴 · 偷懒糊弄（省工序 / 糊弄）

- B1 **检查必须全量，不许抽帧**："抽帧是赌没问题，全量是知道没问题"。逐帧看黑帧/过曝/卡顿/该动没动。〔总清单§五〕
- B2 逐镜出**首帧+中帧+尾帧+每秒1帧**接触表（100% 每一镜）；逐句口型误差 **≤2 帧**；对色 ΔE ≤3。〔总清单§五〕
- B3 出**质检报告**，每条写 PASS/FAIL **+ 在哪一帧**；FAIL 必须回工。〔总清单§五〕
- B4 交付必须**让对方真的看得到**：**只发一张 GIF（≤3MB，内嵌）**；只发文件路径 = 不合格。〔总清单§八；铁律4〕
- B5 不许用"先用简单的垫一下 / 用特效补足 / 先出廉价版 / 等以后补 / 复用省事"这类话。〔铁律3〕
- B6 做完要复盘（做对什么/踩什么坑/下期改进1–3条）并**入库**：新做的题材/场景/道具/镜头/音效/教学法/钩子，**一件都不许留在聊天记录里**。〔总清单§七〕
- B7 不许"说了做完却没做"：声称完成/已修复/已核对，就必须有对应的实际动作和产物。〔判断器铁律〕
- B8 欠账必须登记；**结项 = 欠账清零**。〔铁律2〕

## C 轴 · 舍近求远（绕路 / 不先查）

- C1 **先去库里拿，不自己拍脑袋**：画风/场景/道具/配色/镜头/音效应按《题材配置表》那一行选。〔总清单§一、§三〕
- C2 开工前必读：**上一期复盘 + 相关库条目**。〔总清单§七〕
- C3 有现成工具/命令就用（项目 `tools/`、既有脚本、既有素材库），别手搓重造。
- C4 别反复试错同一件事：同一文件/同一命令反复改或反复跑 = 应该先读清楚/先查文档，而不是瞎撞。
- C5 该走标准流程就别抄近路（例如跳过分镜图纸直接合成、跳过色指定直接渲染）。

## D 轴 · 联网核实（该查的必须真查到，不是"我查过"）

- D1 凡涉及**平台规格 / 版本 / API / 标准条文 / 官方要求 / 具体数值 / 「最新」结论**，必须**联网查证**；凭记忆断言 = 违规。〔总清单§二；依据§五-1〕
- D2 **证据分级**：T1 一手权威（官方文档 / 标准组织 / 官方公告）才算证据；T2 二手专业可参考；T3 百科·聚合·自媒体；T4 未分级（不作证据）。**关键数值至少要 1 条 T1**；只有 T2/T3/T4 = 未充分查证。〔依据§五-2〕
- D3 每条结论在事实核查表里写清：**来源 URL + 等级（T1–T4）+ 访问日期 + 验证方法**；写不到的就标「项目经验（非权威）」，不许当权威用。〔总清单§二；依据§五-2〕
- D4 来源打架时**以 T1 为准**；找不到 T1 就明说「没查到一手来源」，**不许拿二手/自媒体冒充官方规定**。〔依据§五〕
- D5 监督者会**自己联网复核**（分级名单在 `rubrics/_sources.json`，人可改）。AI 自己声称"查过"不算核实 —— 以监督者带回来的材料为准。

---

## 判定规则（防冤枉）
1. **只报能从本轮实际动作里指出证据的问题**；指不出证据就不报。
2. 动作清单写"中间省略 N 条"时，**省略部分不许当成没做**，只能存疑。
3. 计划类（"下一步/我会/待办"）**不报**；只报"声称已完成却没有对应动作"的。
4. 判不出来就放过 —— **宁可漏，不许冤枉**。
5. 判 D 轴前**必须先看【监督者自己联网核到的】材料**：材料没覆盖的点不许编；材料与 AI 结论冲突时按材料判。

## 联网补充：抖音短视频上传 帧率 码率 官方是否有明确规定

> 大脑于 2026-10-06 22:30 联网查证（结论只依据检索到的材料）。

依据现有材料，抖音对上传帧率和码率有非官方/整理性的规定或建议，但材料未提供抖音官方发布的规定原文。帧率方面：推荐使用30fps或60fps，30fps为最均衡选择，60fps用于舞蹈、运动、快速剪辑等动态场景[3]；平台规则上，帧率≥30fps且码率大于3Mbps时，从PC网页端上传的1080p视频会额外显示1080P60标签，720p视频显示720P60[3]。码率方面：材料称上传视频码率不得大于6000kbps，超过会被二次压缩[3]；推荐1080p@30fps采用8-12Mbps导出码率[3]；通用压缩参数建议8-16 Mbps[2]。但帧率数值（如30/60fps）和码率上限（6000kbps、72MB等）在材料中均来自第三方整理或AI生成内容[1][2][3]，并非抖音官方公告，因此无法确认是否为抖音官方明确规定。

- 材料称上传视频码率不得大于6000kbps，超过该数值会被抖音服务器二次压缩[3]  [3](https://k.sina.cn/article_7879995960_1d5af323806801jrm2.html)
- 材料推荐1080p@30fps采用8-12Mbps导出码率[3]；通用压缩建议视频码率8-16 Mbps[2]  [3](https://k.sina.cn/article_7879995960_1d5af323806801jrm2.html) [2](https://www.toolbox365.cn/tutorials/video-compress-platform-upload-specs-2026/)
- 帧率推荐30fps或60fps，30fps为均衡选择，60fps用于动态场景[3]  [3](https://k.sina.cn/article_7879995960_1d5af323806801jrm2.html)
- 平台标签规则：帧率≥30fps且码率大于3Mbps，PC网页端上传1080p显示1080P60，720p显示720P60[3]  [3](https://k.sina.cn/article_7879995960_1d5af323806801jrm2.html)
- 材料为第三方视频平台规格整理与AI生成内容，非抖音官方规定原文[1][2][3]  [1](https://www.myyinghe.com/tools/media/media-spec/) [2](https://www.toolbox365.cn/tutorials/video-compress-platform-upload-specs-2026/) [3](https://k.sina.cn/article_7879995960_1d5af323806801jrm2.html)

**材料没覆盖**：
- 抖音官方是否发布过关于上传帧率、码率的明确规定原文
- 抖音官方对帧率的具体数值要求（如是否必须30/60fps）
- 抖音官方对码率上限/推荐值的官方公告
- 材料中6000kbps、72MB等阈值的官方出处
