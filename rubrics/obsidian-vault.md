# 工作监督 · 判据（Obsidian 知识库）

> 依据：**库内 `AGENTS.md` 的 7 条硬约束** + `第二大脑使用手册.md`。
> 判 D 轴用 `rubrics/_sources.json` 的分级名单（T1 一手权威才算证据）。

## A 轴 · 结构规范（放对地方、写全元数据）

- A1 目录职责：`00_Inbox`=临时收件箱 / `10_笔记`=主题层 / `20_附件`=原始资料 / `30_模板`=模板 / `90_归档`=过时保留。
- A2 **无法确认归属的内容只能进 `00_Inbox`**，不得猜测分类（库规第 6 条）。
- A3 新笔记要有 frontmatter：至少 `type` / `title` / `updated`；标准类还要 `tags`。
- A4 新增主题笔记要挂进对应 MOC（否则等于没进库）。
- A5 `00_Inbox` 不许长期堆积：超过 N 天没动 = 待处理。

## B 轴 · 不糊弄（不许破坏已有内容）

- B1 **不删除笔记正文段落、观点、来源或用户文字**（库规第 1 条）。只允许移动/重命名/新建、改 frontmatter/双链/附件引用。
- B2 移动文件前必须确认源与目标路径，**不能覆盖已有文件**（库规第 4 条）。
- B3 移动后必须扫描并修 `[[双链]]`、`![[附件]]`、Markdown 本地链接（库规第 5 条）。
- B4 日常维护结束前**必须 git 提交**（库规第 7 条），除非工作区没有有效变更。
- B5 系统垃圾/重复内容/低置信度分类先在维护报告里列出，**未获授权不得删除**（库规第 3 条）。

## C 轴 · 不绕路（先查库再动手）

- C1 先读 `AGENTS.md` + `maintenance_prompt.md` 再维护。
- C2 新建前先搜库，避免重复条目；同一主题要合并进已有笔记，别另起一篇。
- C3 用 `30_模板` 里的模板，别手搓格式。
- C4 附件按主题归到 `20_附件`，别散在笔记目录。

## D 轴 · 联网核实（和视频那条同规）

- D1 涉及规格/版本/API/标准条文/官方要求/具体数值/「最新」结论，必须**先联网查再写**。
- D2 证据分级 T1–T4；关键数值至少 1 条 T1，只有 T2/T3/T4 = 未充分查证。
- D3 引用要给 **来源 URL + 等级 + 访问日期**；查不到 T1 就写「没查到一手来源」。
- D4 第三方资料进 `20_附件` 时保留出处，不许改写成自己的结论。

---

## 判定规则（防冤枉）

1. 只报能从本轮实际动作或库体检结果里指出证据的问题；指不出就不报。
2. 计划类（下一步/打算）不报；只报"声称做完却没有对应动作"。
3. 判不出来就放过 —— 宁可漏，不许冤枉。
4. 判 D 轴前必须先看【监督者自己联网核到的】材料；材料没覆盖的点不许编。
